# AI-Powered Security Triage Assistant

A production-style AI web application for a cybersecurity internship. It classifies phishing
emails, SOC alerts, and system logs using a Large Language Model (LLM), explains its reasoning,
assesses risk, extracts Indicators of Compromise (IOCs), and recommends security actions.

## Architecture

The backend follows **Clean Architecture** with strict separation of concerns:

```
Request -> API (FastAPI routers) -> Service (business logic) -> Repository (DB access) -> Model (SQLAlchemy)
                                          |
                                          v
                                   LLM Client (LangChain/OpenAI)
```

- **`api/`** — HTTP layer only: request/response wiring, no business logic.
- **`services/`** — Orchestrates sanitization, LLM calls, IOC extraction, PDF export, stats.
- **`repositories/`** — All SQL/ORM access lives here; services never touch SQLAlchemy sessions directly for queries.
- **`llm/`** — Prompt templates, few-shot examples, the MITRE/OWASP knowledge base, response parsing/validation.
- **`models/`** — SQLAlchemy ORM models (`User`, `Analysis`, `UserSettings`).
- **`schemas/`** — Pydantic request/response contracts, including the strict `LLMAnalysisResult` schema the model must return.
- **`core/`** — Config, security (JWT/password hashing), logging, rate limiting, exception handling.

The frontend is a React + TypeScript SPA with a `pages/ -> components/ -> services/` structure,
Tailwind CSS for styling, and a shadcn/ui-inspired component set (`components/ui/`).

## Tech Stack

**Backend:** Python 3.12, FastAPI, OpenAI SDK, LangChain, Pydantic v2, SQLAlchemy 2.0, Alembic, PostgreSQL
**Frontend:** React 18, TypeScript, Vite, Tailwind CSS, shadcn/ui-style components, Recharts
**DevOps:** Docker, Docker Compose, Git, `.env` configuration, Swagger/OpenAPI (auto-generated by FastAPI), Pytest

**Bonus features implemented:**
- IOC extraction (IPs, domains, URLs, emails, hashes) via `app/services/ioc_service.py`
- MITRE ATT&CK + OWASP Top 10 knowledge base injected into the prompt (`app/llm/knowledge_base.py`)
- JWT authentication (`/api/v1/auth/register`, `/api/v1/auth/login`) with optional anonymous analysis
- PDF export of any analysis (`GET /history/{id}/export`) via ReportLab
- Dark/Light mode toggle (persisted in `localStorage`, Tailwind `dark:` classes)
- Charts (Recharts): risk distribution pie chart + weekly stacked bar chart

> **Note on RAG (ChromaDB):** `requirements.txt` includes `chromadb` and `langchain-community` for
> teams that want to extend `app/llm/knowledge_base.py` into a full vector-store retrieval pipeline
> (embed MITRE/OWASP/IOC playbooks, retrieve top-k per request). The current build ships a
> **RAG-lite** version: a curated static knowledge block is injected directly into the system
> prompt, which is simpler to operate and sufficient for the internship's demo corpus. See
> [Future Improvements](#future-improvements) for the upgrade path.

## Installation

### Prerequisites
- Docker + Docker Compose (recommended), **or**
- Python 3.12, Node.js 20+, PostgreSQL 16 (for manual setup)
- An OpenAI API key

### Quick start (Docker)

```bash
git clone <this-repo>
cd ai-security-triage-assistant
cp backend/.env.example backend/.env      # then fill in OPENAI_API_KEY
cp frontend/.env.example frontend/.env
docker compose up --build
```

- Frontend: http://localhost:5173
- Backend API docs (Swagger): http://localhost:8000/docs
- Backend ReDoc: http://localhost:8000/redoc

## Environment Variables

### `backend/.env`

| Variable | Description | Default |
|---|---|---|
| `OPENAI_API_KEY` | Your OpenAI API key | *(required)* |
| `OPENAI_MODEL` | Chat model used for triage | `gpt-4o-mini` |
| `OPENAI_TEMPERATURE` | Sampling temperature | `0.1` |
| `DATABASE_URL` | Full SQLAlchemy Postgres URL | built from `POSTGRES_*` vars |
| `SECRET_KEY` | JWT signing secret | *(change in production)* |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | JWT expiry | `60` |
| `CORS_ORIGINS` | Comma-separated allowed origins | `http://localhost:5173,http://localhost:3000` |
| `RATE_LIMIT_PER_MINUTE` | Requests per minute per client IP | `20` |

See `backend/.env.example` for the full list.

### `frontend/.env`

| Variable | Description | Default |
|---|---|---|
| `VITE_API_BASE_URL` | Backend API base URL | `http://localhost:8000/api/v1` |

## Running with Docker

```bash
docker compose up --build
```

This starts three services: `db` (PostgreSQL), `backend` (FastAPI on port 8000), and `frontend`
(built React app served by nginx on port 5173, which proxies `/api/*` to the backend).

## Running Locally (without Docker)

**Backend:**
```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # fill in OPENAI_API_KEY and a local Postgres DATABASE_URL
alembic upgrade head
uvicorn app.main:app --reload
```

**Frontend:**
```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

## Prompt Engineering

- **System Prompt** (`app/llm/prompts.py`) defines the analyst persona, the strict JSON schema,
  and explicit prompt-injection resistance instructions (treat submitted content as untrusted
  data, never as commands).
- **Few-shot examples** (phishing email + brute-force log) are sent as prior conversation turns
  to anchor the model's output format and reasoning style.
- **Structured outputs**: the OpenAI call uses `response_format: {"type": "json_object"}`, and the
  response is additionally parsed and validated against a Pydantic schema (`LLMAnalysisResult`) in
  `app/llm/parser.py`, with automatic retries via `tenacity` on transient failures.
- **Grounding**: a curated MITRE ATT&CK + OWASP Top 10 + phishing-indicator knowledge block is
  injected into the system prompt so the model cites real technique IDs instead of hallucinating them.

## Security

- **Input validation**: Pydantic schemas enforce length/shape on every request.
- **Input sanitization**: control characters stripped, HTML entities unescaped, length-capped (`app/utils/sanitization.py`).
- **Prompt injection / jailbreak protection**: heuristic pattern detection flags suspicious
  instructions embedded in submitted content; the system prompt independently instructs the model
  to always treat submitted content as data, never as instructions — defense in depth.
- **Rate limiting**: sliding-window middleware limits requests per client IP (`app/core/rate_limiter.py`).
- **CORS**: explicit allow-list via `CORS_ORIGINS`.
- **Secrets**: all credentials/keys are loaded from `.env`, never hard-coded.
- **Logging & exception handling**: structured logging plus centralized FastAPI exception handlers
  return safe, consistent error payloads (`app/core/exceptions.py`).
- **Auth**: JWT-based authentication with bcrypt password hashing (`passlib`).

## Testing

```bash
cd backend
pytest --cov=app
```

Coverage includes:
- `tests/test_parser.py` — JSON extraction/validation from raw LLM output
- `tests/test_ioc_service.py` — IOC regex extraction
- `tests/test_sanitization.py` — input sanitization + prompt-injection heuristics
- `tests/test_analyze_api.py` — full API flow for `/analyze`, `/history`, `/stats` (LLM client mocked)
- `tests/test_health.py` — health/root endpoints

> Backend tests use an isolated in-memory SQLite database per test via `tests/conftest.py`, so they
> run without a live PostgreSQL instance. The OpenAI call is mocked in API tests so the suite runs
> fully offline and deterministically.

## Future Improvements

- Upgrade the static knowledge block into a full RAG pipeline: embed MITRE ATT&CK, OWASP, and
  internal SOC playbooks into ChromaDB and retrieve top-k relevant chunks per request instead of
  sending the full static list.
- Move rate limiting from in-process memory to Redis for multi-instance deployments.
- Add role-based access control (analyst vs. admin) and per-user history isolation enforcement.
- Add a feedback loop (analyst confirms/overrides classification) to fine-tune prompting over time.
- Add streaming responses (Server-Sent Events) so the UI can show partial analysis while the LLM is generating.
- Add attachment/file upload support (e.g., `.eml` files) with automatic header/body extraction.
